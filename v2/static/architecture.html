1. 目標與不變原則

這個專案只做一件事：把派網合約網格（futures grid）每天的倉位與利潤差，用可追溯的方式記下來。不是交易機器人，也不改倉。

硬限制（改程式時不要破）

  • 只呼叫 GET。白名單以外的私有路徑一律擋掉。不建立、不調整、不暫停、不取消 Bot。
  • API key 只開 Bot reading（加上錢包讀取）。金鑰檔 PIONEX API.txt 不進 Git、Notion、Excel、日誌。
  • 公開 GitHub（forsmileangel/Pionex-Grid）只同步程式。真實 xlsx、sqlite、snapshot、利潤數字留本機。
  • v1 的 08:00 Excel 排程是生產基準，v2 開發期間不要改它的工作目錄或腳本。

2. 雙線架構

Excel 每日紀錄 資料夾 D:\My-project\pionex grid record。每天 08:00 跑 pionex-grid-daily.ps1，寫長期 Excel。識別 Key 是「交易對 + 建立時間」。
SQLite 本機儀表板 資料夾仍叫 pionex grid record-v2（git worktree），畫面上不叫 v2。用 SQLite 記帳 + 本機 HTML（127.0.0.1:8787）。同一天 capture 覆蓋當天，隔天才多一列。開／關伺服器用 儀表板開關.cmd。
共用收集器 兩邊都跑 pionex-grid-api.mjs（Node、HMAC GET）。v2 多讀 finished 清單、錢包、Mark、資金費，再交給 Python ingest。

為什麼拆兩條：v1 已經在記帳，不能在改欄位時把 08:00 弄壞。v2 用資料庫重做儀表板與長天期報表，滿意再考慮取代或接 Portfolio Tracker。

收集器不會在儀表板開著時一直打 API。HTML 只讀 SQLite。要新數字必須再跑 python -m v2.capture 或 capture-v2.cmd，然後重整瀏覽器。

4. 資料怎麼記住

金額在 SQLite 用整數 × 108 存，避免浮點誤差。一天一筆總帳（daily_summary），一倉 × 一天一筆明細（daily_grid_profit）。倉位主檔是 grid_positions（主鍵 bu_order_id），每次 capture 再寫一張 grid_snapshots。

當日利潤（日記帳，Excel 用這條）

  1. 資料庫是空的：整批標 baseline，當日利潤 = 0。只記住當天的累計網格利潤。
  2. 隔天還在跑的舊倉：continue，當日利潤 = 今天 GridProfit − 昨天記住的 GridProfit。
  3. 新開的倉：new，當天也是 0，隔天起才開始減。
  4. finished 清單對得上、資料完整：closed，最後一天仍算差額。
  5. 人消失但 finished 對不上：closed_unresolved，當日利潤空白，不要猜。

同一日再 capture 會刪掉該日 summary／明細／snapshot 再寫。所以 8/25 按十次還是只有 8/25 一列。8/26 第一次成功才會出現第二天，且通常不是 0（除非過夜網格利潤完全沒動）。

漏抓的日子不會自動補。v1 的 08:00 不會寫進 v2 sqlite。長天期 Excel 要靠每天至少一次 v2 capture。

6. 最終採用的計算

項目公式注意
倉位大小API Investment不要用倉位數量 × 現價（那是名目，會跟標的「很歪」）。
畫面單天 %該列單日利潤 ÷ Investment目前倉位頁的單日利潤是 24h；每日詳情是日記帳。
頂部 24h 總倉位%Σ gridProfit24h ÷ Σ Investment顯示在「過去 24 小時總利潤」的 TWD 下面。
趨勢盈虧Investment × 槓桿 × (Mark−開倉)/開倉 × 方向做空方向為 −1。對齊派網單倉總損益頁。
目前總損益趨勢 + 網格利潤不加資金費。資金費用 totalFundingFee 另列。
網格年化網格利潤 / Investment / 持有天數 × 365API 沒有現成年化。
總年化總損益 / Investment / 持有天數 × 365總損益仍不含資金費。
U 本位強平距離(Mark−強平)/Mark（多）或 (強平−Mark)/Mark（空）結果必須在 0–100%。負的就夾成 0，不要倒數。
幣本位強平價合約價太小（例如 0.000769）時取倒數ETH 強平應對齊 UI 約 1300，不是 inverse。自動偵測：距離為負或與 Mark 差兩個數量級。
台幣USDT × 臺銀 USD現金買入 × USDT/USD用來對齊派網「約 172 萬」口徑，不是中間價 USD/TWD，也不是 MAX 的 USDT/TWD。
單日利潤（U 本位）今天畫面 GridProfit − 昨天加倉本金、舊 profitReinvest 存量不算當天賺到。
單日利潤（幣本位）(今天累積幣 − 昨天累積幣) × 抓取當下現貨價ETH 8/26 是 +0.00154 ETH × ~2444 ≈ +3.8U，不是 USDT 庫存差 −7.48。幣價把舊庫存重估的部分記成 fx_gap，月底再看。
累積（月曆）當天還開著的倉，畫面 GridProfit（USDT）加總幣本位日子，單日加總可以不等於累積的日差：單日不含幣價，累積含。
真實網格總利潤基準日之後用單日（幣本位用新增幣×當日價）往上加舊存量與加倉不加。還沒複投／提取／關倉時，U 本位會跟畫面加總接近；幣本位會跟畫面分岔，那是刻意的。

7. 加倉 vs 複投怎麼分

程式不會改你的倉。每天只拿兩張已存快照（昨天、今天）比對：倉位大小變了多少、網格利潤變了多少。U 本位看畫面 USDT；幣本位（ETH）看累積幣的增減，再乘當天抓取價，不當成畫面 USDT 庫存差（否則 ETH 跌就會被誤判成虧損或提取）。單元測試裡的 AMD 複投、待確認案例是假資料；本機真實帳本從 2026-08-25 起。

實際定義（你對過的）

  • 複投：把已經賺到的網格利潤打進倉位。以 AMD 為例，倉位 3500、網格利潤 1418 時若複投，倉位會變成約 4918，網格利潤加總會少掉約 1400（從接近 0 再算）。通常沒有 100～200U 以上不會想做。
  • 加倉：只是本金變多。網格利潤仍正常走、沒有突然少一大截。額度通常 ≥ 200U（8/26 MUX +417、網格 +5）。不到 100U 很少加倉；100～200U 只在湊整時才較像加倉，且網格不該大跌。

判斷順序在 v2/store.py 的 _classify_event。先看你是否已在月曆上手動點過「這是加倉／這是複投」；沒點才走自動規則。加倉門檻用 200U 而不是 100U：誤把複投當成加倉，真實總利潤會少一截；100～200U 又碰上網格下跌時改待確認，比硬判更低風險。

條件（相對前一天同一筆倉）判定單日利潤怎麼算
倉位增加 ≥ 20U，且網格利潤少掉 ≥ 20U，且兩筆金額接近（差距 ≤ 50U 或較大那邊的 25%） 複投 最像「網格打進倉位」。金額對得上時，即使不到 100U 也算複投。
派網 profitReinvest 當天增加 ≥ 20U，同時網格利潤也少掉 ≥ 20U 複投 旁證，不當唯一證據。
倉位增加不到 100U，網格利潤少掉 ≥ 20U（金額不一定接近） 複投 這種額度很少加倉，比較像小額複投。真實總利潤把掉下去的網格加回。
網格幾乎沒重置（少掉不到 20U，或還在往上走），倉位卻變多 加倉 含 100～200U 湊整。本金不列為利潤。
倉位增加 ≥ 200U，網格利潤少掉不到 100U 加倉 典型加倉（8/26 MUX +417、網格 +5）。
倉位增加 100～200U 且網格少掉 ≥ 20U，或倉位增加同時網格少掉 ≥ 100U 但金額對不上 待確認 100～200U 很少加倉，大跌又對不齊也不敢自動判。月曆該列可點「這是加倉／這是複投」。單日先只記網格自己的加減。
其餘（倉位沒變、或只有幾 U 的網格晃動） 續存 U 本位：今天畫面網格 − 昨天。幣本位：今天累積幣 − 昨天累積幣（×當日價才進單日）。ETH 跌使畫面 USDT 變少，若幣還在增加，是續存不是提取。

刻意不算複投的情況

  • 派網 profitReinvest 只是累積存量。TSMX／SNDKX 在 8/25 快照裡就已經有 300～400U 的存量，8/26 倉位沒變、網格利潤還在往上走，所以那是以前複投過，不是那天又複投。不當日利潤，也不加進真實網格總利潤——我們從基準日才開始記。
  • 倉位變大但網格利潤一切正常 → 加倉。8/26 日曆曾經出現的 +1253，就是把這些存量／加倉誤當成當天複投。
  • 網格利潤自己掉一點、倉位沒變（例如 ETH −7.5U）→ 續存，不是提取、也不是複投。

8/26 自動結果：MUX 加倉；其餘 14 筆續存；沒有待確認。真實帳本沒有被單元測試改倉，測試是另開暫存 sqlite 用假快照。

8. 解決問題的過程

下面是實作時對過的坑。改計算前先看這裡，避免又繞回去。

現象誤判後來怎麼定
倉位大小跟標的差很多（例如 6959 vs 3500） 用持倉數量 × 現價當大小 大小 = Investment。% 的分母也是它。
ETH 強平距離爆掉，UI 是 1300.34、程式是 0.000769 所有倉都當 U 本位；或全部倒數 大多數是 U 本位。只有幣本位／數量級差才倒數。U 本位距離為負 → 夾 0。
AMDX 總利潤對不齊 總損益把資金費加進去；或用錯資金費欄 總 = 趨勢+網格。資金費顯示 totalFundingFee（約 −152.6 那檔）。
錢包台幣 174.1 萬，派網約 172.5 萬 USDT≠USD 就夠解釋（其實只差約 350 元） 市場 USDT/TWD 更高。對齊派網要用臺銀現金買入×USDT/USD（約 31.49），不是 er-api 的 31.81。
Excel 不像長天期、沒有單日% 把當下快照再匯一次就好 依 capture_date 出總覽＋明細＋矩陣。% 用已存利潤／投資現算。第一天仍是 0。
HTML 開著，24h 利潤以為會跳 server 會背景打 API 不會。頻率 = 你手動 capture 的次數。
8/26 月曆單日 +1253；真實網格總利潤約 7980 把派網 profitReinvest 舊存量、或倉位變多，當成那天複投並加進真實總利潤 複投必須網格利潤明顯掉進倉位。MUX +417 本金、網格 +5 → 加倉。舊存量不加真實。單日約 +55；真實應跟網格利潤加總一樣（約 6781）。

9. 日常怎麼跑

  1. 雙擊 儀表板開關.cmd 可開啟或關閉本機伺服器。登入後工作排程 Pionex Grid SQLite Dashboard 也會自動開（不開瀏覽器也可以，網址仍是 8787）。
  2. 目前倉位一鍵即時抓派網，存在 v2-data/live-snapshot.json，不寫每日 sqlite、不 PATCH Gist。倉位紀錄才是每日快照。備援「寫入今日倉位紀錄」要點兩次，且 POST 必須帶台北今天日期。
  3. 要新資料：雙擊 capture-v2.cmd（或 python -m v2.capture）。同日覆蓋、隔日新增。
  4. 硬重新整理儀表板。點表頭可排序。
  5. 長天期報表：頁上「匯出 Excel」。看的是資料庫歷史，不是再抓一次派網。
  6. v1 Excel 繼續 08:00 自己跑，跟 v2 互不覆寫。

金鑰仍用 v1 資料夾的 PIONEX API.txt（兩行：key、secret）。v2 capture 預設指向那裡，不要複製進 Git。

10. 刻意沒做、之後可改

  • 待確認目前沒有真實列。 規則已寫好，月曆有按鈕，但 8/26 全部自動判定完成。若之後同一天又加倉又大跌網格、金額對不上，再請你點一次。
  • 08:05 shadow capture。 install-v2-daily-capture.ps1 另建任務，不改 v1 08:00。沒設這任務就不會自動出第二天。
  • 儀表板不即時。 若要開著就更新，需要獨立的輪詢 capture（注意 API 頻率與同日覆蓋）。
  • Portfolio Tracker 讀 Gist 第二檔。 契約寫在專案根目錄 PORTFOLIO-TRACKER-GIST.md。改 ledger JSON／Gist 檔名／schema 前必讀，否則 PT 網格頁會空白。ingest 成功後 PATCH pionex-grid-ledger.json；失敗只略過，不回滾 sqlite。PT 只讀、不持有派網金鑰、不改 holdings 檔。本機 8787 仍只綁 127.0.0.1、不加 CORS。
  • 派網沒有官方 USDT/TWD。 現在用臺銀現金買入對齊 App 顯示。若派網改口徑，先對錢包總市值，再改 v2/fx.py。
  • 基準日當日利潤永遠是 0。 這是為了避免把歷史累計利潤當成那天賺到的。不要為了「看起來有數字」拿掉。正式基準日是 2026-08-26（8/25 試跑已清空）。
改計算時的建議順序：先對單一網格（AMDX 那套總損益／年化），再對錢包台幣，最後才動 Excel。U 本位強平不要為了修一筆 ETH 而去倒數所有倉。
