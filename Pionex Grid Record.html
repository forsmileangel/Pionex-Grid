派網合約網格自動記錄流程

API-only、每日 08:00、長期 Excel 日差帳｜最後更新：2026-08-25

目前範圍只記錄派網合約網格，動態支援新增與關倉。
資料來源Pionex 唯讀 API；不使用 OpenCLI、不操作瀏覽器。
安全原則只呼叫 GET；不建立、調整、減倉或關閉機器人。
屯幣寶處理目前官方公開唯讀 API 的運行中清單沒有回傳屯幣寶，本版直接跳過。Excel 保留獨立的「屯幣寶記錄」頁籤，但不寫入每日數字，也不併入合約網格總和。

資料夾結構

檔案用途
D:\My-project\pionex grid record\PIONEX API.txt第一行 API key、第二行 API secret。只在本機讀取，禁止上傳、貼到 Notion 或提交 Git。
pionex-grid-api.mjs分頁取得所有 running futures_grid，逐筆取得詳情；幣本位利潤用公開行情換算 USDT。
pionex-grid-daily.ps1完整性檢查、日差計算、累計、關倉辨識、Excel 寫入與備份還原。
pionex-grid-backfill.ps1使用已保存的 JSON 快照手動補讀歷史日期。
data\pionex-grid-history.xlsx長期帳本；包含「每日網格差額」與獨立「屯幣寶記錄」兩頁。
data\pionex-grid-daily.log只記錄執行狀態、筆數與錯誤，不寫入 key/secret。

每日流程

08:00 啟動 PowerShell。
API 分頁抓取全部 running futures_grid。
逐筆取得利潤與投資額，確認筆數一致。
完整才寫入 Excel；失敗則保留原檔。

第一個 08:00 執行會以 ReplaceDate 取代當日暫定基準；後續排程不帶 ReplaceDate，避免同日重複。

Excel 日差邏輯

  1. 網格識別鍵是「交易對 + 建立時間」，不是畫面順序。
  2. 持續網格：每日利潤 = 今日網格利潤 - 前次網格利潤。
  3. 新網格：第一次出現視為基準，當日每日利潤為 0。
  4. 完整快照中消失的既有網格：新增一列「關倉」，不把缺資料誤算成 0。
  5. 日總計只加總目前 API 回傳的有效合約網格；屯幣寶永遠不進入此總計。
  6. 每次寫入前建立 .xlsx.bak，若 Excel 寫入失敗會還原原檔。

API 讀取範圍

正式程式只允許以下讀取端點：

  • GET /api/v1/bot/orders：status=running、buOrderTypes=futures_grid，使用 pageToken 讀完所有頁。
  • GET /api/v1/bot/orders/futuresGrid/order：逐筆取得詳情。
  • GET /api/v1/market/tickers：只在幣本位合約需要時取得現貨換算價。

官方參考：Bot API 認證、Bot API 規格、API key 權限。

手動補讀

若 08:00 失敗，先保存當下 API 快照，再以指定日期寫入：

node pionex-grid-api.mjs --output data\snapshot-2026-08-25.json
powershell -ExecutionPolicy Bypass -File pionex-grid-backfill.ps1 -SnapshotJson data\snapshot-2026-08-25.json -CaptureAt 2026-08-25T08:00:00+08:00

沒有保存的歷史快照，就無法事後重建當天的網格利潤差；腳本會拒絕偽造資料。補讀同一日期前，請確認該日期沒有成功紀錄，或明確使用基準替換流程。

維護規則

  • 不要把 PIONEX API.txt 加入 Git、雲端同步、Notion、Excel 或 log。
  • API key 只需要 Bot reading 權限；不需要 Bot trading。
  • 若 API 回傳筆數不足、詳情缺欄位、行情換算失敗或 key/secret 錯誤，程式不寫 Excel。
  • 新增網格會自動新增列；消失的既有網格會在下一個完整快照標記關倉。
  • 若更換電腦，先複製程式與 Excel，再在新機建立相同的 API 憑證檔與 08:00 排程。
